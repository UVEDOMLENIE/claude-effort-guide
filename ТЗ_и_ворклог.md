# ТЗ и ворклог: справочник «Модель × Effort × Расход»

Документ ведётся итерационно. Каждая новая версия добавляет запись в ворклог и, если нужно, правит требования. Сумбур обсуждения здесь причёсан, смысл сохранён.

## 1. Цель

Сделать памятку, по которой человек с уставшим мозгом за пять секунд выбирает модель Claude и уровень effort под задачу и понимает, во сколько это обойдётся. Расход считается относительно Haiku, самой дешёвой модели. Памятка должна быть честной: цифры с замеров, оценки помечены как оценки.

Для кого: пользователь и его коллеги, вайб-кодеры без глубокого технического бэкграунда. Побочная цель: учебный материал о том, как устроены модели, effort и ultracode в Claude Code.

## 2. Требования

### Содержание
- Одна таблица: модель × effort × расход × для чего. Расход в разах и в процентах от Haiku, обе формы обязательны.
- Все цифры для одного агента. Ultracode в таблице равен extra; про риск бригады — отдельный текст.
- Ступени называются как в приложении: low, medium, high, extra, max, ultracode. Внутреннее имя xhigh упоминается один раз как синоним extra.
- У каждой связки оценка одним словом: норм / есть умнее / спорно / устарело, по единой объяснённой логике.
- У каждой связки роль (кто это: Исполнитель, Помощник, Мастер, Инженер, Архитектор, Учёный, Контролёр, Бригада; Гонщик для fast) и потолок: самая трудная задача, которую связка вывозит.
- Роли описаны отдельно: что делает, какие связки подходят, примеры-кейсы.
- Старые модели (Sonnet 4.6, Opus 4.6, Opus 4.8, Fable 5) вынесены в конец, с ответом «есть ли плюсы».
- Примеры универсальные, понятные ребёнку: не из частных проектов пользователя.
- Пояснение про ultracode: что это технически, почему при одном агенте равен extra, почему может привести к перерасходу, как ограничить агентов словами.

### Форма
- Главный файл — минималистичный Markdown (ПАМЯТКА.md). Пояснения, аудит цифр и ТЗ — отдельными файлами.
- HTML-справочник: внутри максимально кислотный и интерактивный, снаружи серьёзное имя файла. Кнопка «кринж выкл» останавливает анимации. Кнопка «перегенерировать скин» и «дефолт».
- PDF A4 и обои 1920×1080 — минималистичные, без кислоты, чтобы повесить на стену у коллег.
- Шрифты крупные (Full HD, уставшее зрение). Заголовок в одну строку.
- Статические пояснения убраны из верха страницы во всплывающие подсказки при наведении, с кнопкой «пояснялки вкл/выкл». Статические пояснения остаются только под элементами, к которым относятся.
- Бегущая строка вдвое выше; по умолчанию несёт общее пояснение, при выборе ячейки — фразу про выбранную связку.
- Блоки страницы отличаются едва заметным оттенком фона.
- Роли кликабельны: по клику показываются кейсы и подсвечиваются подходящие ячейки.
- Несколько примеров-кейсов с переключением.
- Язык сдержанный, без бравады, без программистского жаргона там, где можно без него.

### Процесс
- Версии сохраняются в папке архив и в git.
- После записи файлов — отдельный проход вычитки глазами неподготовленного читателя, с фиксацией найденного и правкой.
- Без многоагентных воркфлоу: вся работа одним агентом.

## 5. Принятые решения

- Расход считается за задачу по замерам Anthropic, а не по цене токена: сильная модель тратит меньше токенов. Для мелких массовых дел — по цене токена, это сказано под таблицей.
- Единица — одна задача на Haiku. Якорь: Haiku ≈ 1/10 цены Opus 5 high за вопрос.
- extra = high × 1.5, max = high × 2.5 — оценки, помечены.
- Ultracode при одном агенте = extra. Риск бригады описан текстом и правилом 5, не числом в таблице.
- Оценка по правилу: спорно — есть вариант и дешевле на 30 %+, и не глупее (или равный с риском перерасхода); есть умнее — за те же деньги умнее; норм — иначе. Скорость fast — польза.
- Названия ступеней как в приложении.
- Старые версии не удаляются: архив и git.

## 6. Отвергнутое

- Многоагентный воркфлоу для сборки памятки: избыточен.
- Две колонки «токен / задача» в главной таблице: непонятно.
- Значки ✔/~ в главной таблице: шум (остались в аудите).
- Ярлыки НОРМ / СПОРНО / УСТАРЕЛО капслоком и «не имеет смысла»: заменены на норм / есть умнее / спорно.
- Арифметика в примере (×615 против ×5 200): не читается.
- Пример из частного проекта (Homebox): непонятен посторонним.
- Ultracode как тумблер со слайдером агентов и ultracode как «extra × 10» в таблице: не соответствует ползунку и вводит в заблуждение.
- «Ты сейчас здесь», «сюрприз», «вот твои +100500 %»: бравада.
- Восемь ролей без привязки к таблице и четыре роли без кейсов: первое перегружает, второе не цепляет. Итог — восемь ролей с кейсами и привязкой к связкам.

## 7. Что проверено, что оценка

Проверено: цены за токен; расход Opus 5 low / medium / high, Sonnet 5 high, Fable 5.1 low / medium / high, Sonnet 4.6, Opus 4.8, Fable 5 (замеры Anthropic); Ultracode = xhigh + разрешение на бригаду (данные сессии, системная инструкция, issue #69653).

### Перед публикацией (обязательно)

- **PDF памятки вернуть к формату второй версии.** Начиная с третьей версии PDF — это снимок сетки из HTML, читать невозможно. Во второй версии PDF был настоящей таблицей: Модель | Effort | Расход | Роль · потолок, где название роли жирным, потолок обычным шрифтом, короткие фразы, отметка ✔ у связок. Этот формат оставить как есть, внести только критические правки: extra вместо xhigh, все цифры для одного агента, ultracode = extra (убрать строки «×12 агентов» и десятки тысяч процентов внизу), проценты как в шестой версии. Под таблицей легенда: «✔ — рекомендуется к использованию» (✔ ставить у связок с оценкой «норм»).
- **MD-памятку сблизить со второй версией по форме.** Внимание на второй версии держится лучше: короче тексты в ячейках, роль жирным и сразу потолок, отметки ✔. Убрать сокращения вроде «Гонщик, то же» — у fast каждая строка должна читаться сама по себе, без отсылки к строке выше. Цифры и оценку оставить шестой версии.
- **Аудит правил.** Собрать все правила из всех версий памятки (6 в v1, 7 в v2 и v3, 5 в v4–v6), оставить только те, которые реально полезны и запоминаются: короткие, как афоризмы, понятные без подготовки. Не больше семи, можно меньше; заполнять «для количества» нельзя, лучше пусть будет три.
- **Причесать все документы к единому виду.** Вычитать ПОЯСНЕНИЯ.md (пользователь его ещё не читал), АУДИТ_цифр.md и ТЗ_и_ворклог.md, чтобы термины, названия ступеней и цифры совпадали с памяткой шестой версии.

| **Netlify / Vercel / Cloudflare Pages** | аккаунт, перетащить папку | простой хостинг статики, свой поддомен | MD не рендерится сам, нужна конвертация в HTML |
| **Просто отправить файлы** | ничего | работает без интернета, если не нужны шрифты | MD выглядят сыро; ссылки между файлами работают только в папке |

Рекомендация: сейчас — артефакт claude.ai, чтобы скинуть человеку ссылку; для постоянного места — GitHub с Pages, там Markdown красив без усилий, а git уже заведён.

Условия от пользователя: выкладывать только последнюю версию; в GitHub — только в аккаунт пользователя, не в чужой; перед публикацией сначала выполнить пункты «перед публикацией» из раздела 8.

Что подключено к сессии на 15.09.2026 (проверено): GitHub под аккаунтом **UVEDOMLENIE** (7 репозиториев, среди них mini_game_no_js_vercel — значит, Vercel тоже когда-то использовался); claude.ai для артефактов под аккаунтом пользователя; Google Drive, Gmail, Google Calendar; Notion; Figma; Zapier. Не подключены: GitLab, Vercel, Netlify (аккаунтов в сессии нет). Из этого набора для сайта подходят GitHub Pages и артефакт claude.ai; Notion может отдельно показывать MD-документы как страницы, но не справочник.

## 9. Как обновлять

- Перед правкой скопировать текущие файлы в архив с номером версии, после правки — git commit.
- Цифры менять только в АУДИТ_цифр.md с источником, затем переносить в памятку и справочник.
- Обои: headless Chrome, `--screenshot`, окно 1920×1080, адрес файла с `?wall=1`. PDF: `--print-to-pdf`. Предпросмотр печати на экране: `?print=1`.
- После правок — проход вычитки глазами неподготовленного читателя, найденное записывать в АУДИТ_цифр.md.
